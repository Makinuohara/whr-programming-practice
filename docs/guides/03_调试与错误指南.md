# WHR 调试与错误指南

WHR 的错误接口是语言的一部分：错误写到标准错误，不混入正常输出；CLI 返回不同的非零退出码；有源码位置的诊断包含文件、行和列。完整定义见[错误模型](../language/03_错误模型.md)。

## 1. 先按固定流程定位

遇到程序不能运行时，不要先猜解释器内部实现，按下面顺序缩小问题：

1. 用 `python -m whr --version` 确认调用的是当前仓库解释器。
2. 用 `python -m whr --check path/to/program.whr` 分离词法/语法问题。
3. 如果 `--check` 通过，再运行程序并分别保存 stdout、stderr 和退出码。
4. 根据错误类别决定看源码、语法结构、运行时值还是文件路径。
5. 把程序缩减为最小复现，只保留产生错误所需的几行。
6. 修复后先重复最小复现，再运行相关黑盒用例，最后运行全量测试。

检查命令示例：

~~~bash
python -m whr --check examples/guide_demo.whr
python -m whr examples/guide_demo.whr >out.txt 2>err.txt
echo $?
~~~

`--check` 只检查，不执行 `show`、`read` 或函数；因此它通过并不代表运行时输入和类型一定正确。

## 2. 退出码速查

| 退出码 | 类别 | 发生阶段 | 首先检查 |
|---:|---|---|---|
| 0 | Success | 检查或执行成功 | 输出是否符合预期 |
| 2 | UsageError | CLI 参数 | 文件数量、选项拼写 |
| 65 | LexError | 词法分析 | 字符、字符串、转义 |
| 66 | ParseError | 语法分析 | 分号、括号、块和语句位置 |
| 70 | RuntimeError | 执行 | 值的类型、名称、索引、字段和调用 |
| 74 | IOError | 读文件 | 路径、权限和 UTF-8 编码 |

有源码位置的错误格式是：

~~~text
FILE:LINE:COLUMN: CATEGORY: MESSAGE
~~~

UsageError 没有源码位置；文件打开失败使用：

~~~text
FILE: IOError: MESSAGE
~~~

默认 CLI 不会把 Python traceback 当作用户错误输出。如果 stderr 出现 Traceback，应把它当作解释器缺陷报告，而不是修改 WHR 程序来绕过。

## 3. LexError：先修源码字符

词法错误发生在解析前，程序语句不会执行。常见原因有非法字符、未知转义、未闭合字符串和字符串中的原始换行。

错误示例：

~~~whr
show(@);
~~~

可能的诊断：

~~~text
bad.whr:1:6: LexError: unexpected character '@'
~~~

修复：

~~~whr
show("@");
~~~

转义只允许 `\n`、`\r`、`\t`、`\"` 和 `\\`。例如 `\q` 不是合法转义。字符串中的 `#` 是数据，不会开启注释；字符串外的 `#` 才开始单行注释。

排查要点：

- 文件是否为 UTF-8；
- 是否把中文标点、全角引号或全角分号复制进源码；
- 字符串结尾是否缺少双引号；
- 数字是否使用了小数点、前缀或 Unicode 数字。

## 4. ParseError：让结构和分号完整

语法错误发生在执行前。每条变量声明和表达式语句都要用分号结束，代码块要有成对花括号。

错误示例：

~~~whr
let total <- 1
~~~

修复：

~~~whr
let total <- 1;
~~~

赋值左侧只能是变量、数组索引或结构字段。例如 `1 <- 2;`、`show(1) <- 2;` 都不是合法赋值目标。`give` 只能出现在函数体内，`break` 和 `continue` 只能出现在循环体内。

特别注意结构构造的冻结语法：

~~~whr
shape Point {
    x;
}
let point <- form Point { x: 1 };
~~~

必须使用 `form`。写成 `Point { x: 1 }` 会与 `when ok { ... }` 这类控制流块产生歧义，当前规范和解析器都不接受这种旧写法。

## 5. RuntimeError：检查运行时值

运行时错误表示源码语法合法，但实际值不满足操作要求。错误发生前已经写出的正常输出会保留。

### 5.1 严格布尔和无隐式转换

错误：

~~~whr
when 1 {
    show("yes");
}
~~~

修复为显式比较：

~~~whr
when count > 0 {
    show("yes");
}
~~~

同理，字符串和整数不能直接相加：

~~~whr
show("score=" + 95);
~~~

应写成：

~~~whr
show("score=" + to_string(95));
~~~

### 5.2 未定义名称和作用域

错误：

~~~whr
{
    let local <- 2;
}
show(local);
~~~

块结束后 local 不存在。需要在块外使用的值，应在外层先声明，再在块内赋值；需要保留局部性时，则把使用也放在块内。

### 5.3 数组错误

数组下标从 0 开始，且必须是整数。以下程序会产生越界错误：

~~~whr
show([1][1]);
~~~

负数下标也不表示倒数位置。先用 len 检查范围，或确保循环条件是 `i < len(items)`。空数组调用 pop 会产生运行时错误。

### 5.4 结构字段错误

构造时必须提供所有声明字段，不能重复或添加未知字段：

~~~whr
shape Point {
    x;
    y;
}
let point <- form Point { x: 1 };
~~~

应该补齐：

~~~whr
let point <- form Point { x: 1, y: 2 };
~~~

读取或写入不存在的字段也会失败。结构实例字段是可变的，但不能动态添加字段。

### 5.5 函数和标准库参数

用户函数要求精确参数数量；调用 craft add(a, b) 时只传一个参数会得到参数数量错误。标准库同样检查参数类型和数量：read 最多一个字符串提示，len 只接受字符串或数组，push 的第一个参数必须是数组，to_int 不接受 `+1` 或带空格的字符串。

## 6. IOError 和 UsageError

文件不存在：

~~~bash
python -m whr missing.whr
~~~

会返回 74，并输出带文件名的 IOError。文件不是合法 UTF-8 时也属于 IOError；请检查保存编码，不要把乱码当成 WHR 字符串语法问题。

CLI 用法错误示例：

~~~bash
python -m whr --unknown
python -m whr one.whr two.whr
~~~

这类错误返回 2，诊断以 UsageError 开头且没有行列号。

## 7. 输入输出调试技巧

`show` 是最简单的观察手段，但直接字符串不带引号，复杂值中的字符串才会带引号。需要确认类型时使用：

~~~whr
show(type_of(value), to_string(value));
~~~

`read` 遇到 EOF 返回 null；不要把 EOF 当成空字符串。调试交互程序时给固定输入：

~~~bash
printf 'Alice\n' | python -m whr program.whr
~~~

提示文本不换行，所以看到提示和后续输出粘在同一行是规范行为，不是丢失换行。

## 8. 修复后的验证清单

每次修复后执行：

~~~bash
python -m whr --check path/to/program.whr
python -m whr path/to/program.whr
python -m tests.run_all --filter relevant_category
python -m unittest discover -s tests -p 'test_*.py'
~~~

如果错误消息、行列或退出码发生变化，不要只更新期望文件；先确认是否违反冻结规范，再同步记录兼容性变化。完整错误模板见[错误模型](../language/03_错误模型.md)，规范行为案例见[预期行为文档](../language/04_规范示例与预期行为.md)。
