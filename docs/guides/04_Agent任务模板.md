# WHR Agent 任务模板

下面的模板用于把一个 WHR 编程任务交给编程 Agent。复制后只填写方括号内容；没有明确授权的能力不要自行发明。语言边界和命令以项目内的[开发指南](02_开发指南.md)、[冻结规范](../language/01_WHR语言规范.md)和[标准库](../language/02_标准库.md)为准。

## 可复制模板

~~~text
你负责在 WHR v1.0 中完成下面的小任务。

### 需求
- 目标：[用一句话说明程序要解决什么问题]
- 入口文件：[例如 apps/demo/main.whr]
- 需要输出：[逐行写出稳定的期望文本]
- 固定输入：[如果需要 read，写出每一行输入；没有则写“无输入”]
- 边界：[空数组、EOF、零值、错误输入等]

### 允许使用的语言能力
- 基本类型：integer、string、boolean、null
- 数组：字面量、整数下标、len、push、pop
- 结构：先 shape 声明，再用 form Type { field: value } 构造
- 控制流：when/otherwise、repeat while、break、continue
- 函数：craft、give、递归和词法闭包
- 标准库：[列出本任务实际需要的 show/read/len/push/pop/to_int/to_string/type_of]

### 明确约束
- 必须使用冻结 WHR v1.0 语法；结构构造必须写 form，不能写旧草案的 Type { ... }。
- 条件必须是 boolean；不要依赖数字、字符串或 null 的隐式真值。
- 不做隐式类型转换；字符串和整数连接要显式调用 to_string。
- 不使用 WHR v1.0 没有的文件、网络、随机数、时间、模块或异常捕获功能。
- 保持输出确定；不要加入随机行为、当前时间或未声明的全局状态。
- 除非我明确要求，不修改解释器、冻结规范或其他无关目录。

### 交付内容
- [需要新增或修改的 .whr 文件]
- [需要新增的黑盒 .stdout/.stderr/.json 文件]
- [需要补充的说明或测试]

### 验证
1. 先运行：
   python -m whr --check [入口文件]
2. 再运行固定输入：
   [把输入通过管道传给 python -m whr 的命令]
3. 确认 stdout、stderr 和退出码与上面的期望完全一致。
4. 运行相关黑盒用例：
   python -m tests.run_all --filter [目录或标签]
5. 最后运行：
   python -m tests.run_all
   python -m unittest discover -s tests -p 'test_*.py'

### 停止规则
- 如果需求需要冻结规范没有的能力，先停下并报告缺口，不要擅自扩展语言。
- 如果语法检查失败，先修复 Parse/Lex 错误，不要用运行时现象掩盖。
- 如果实际输出与期望不同，保留最小复现、完整 stderr 和退出码，报告差异。
- 如果测试失败，先判断是程序错误、期望文件错误还是解释器回归；不要删除失败用例。
- 完成后报告修改文件、验证命令、实际输出摘要和未完成项；不要声称未运行的命令已经通过。
~~~

## 使用这个模板的原因

- 先写输入输出和边界，Agent 才能把“功能完整”变成可观察行为，而不是只写一段看似能运行的代码。
- 把允许能力和禁止能力分开，能阻止 Agent 把 Python、JavaScript 或旧版 WHR 语法带进来。
- 先 `--check` 再执行，能快速区分源代码结构错误和运行时值错误。
- 固定黑盒验证命令和停止规则，能保留失败证据，也方便验收时解释 Agent 做了什么。

## 适合验收演示的补充要求

如果任务用于课堂展示，可以在需求末尾追加：

~~~text
请同时给出：
1. 一段 30 秒内能运行的固定输入演示；
2. 说明使用了哪个 shape、哪个函数和哪一个循环；
3. 一个故意触发的错误案例，以及它的类别和退出码；
4. 一句话说明为什么使用 form、为什么没有依赖隐式布尔转换。
~~~
