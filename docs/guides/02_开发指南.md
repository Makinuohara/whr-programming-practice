# WHR 开发指南

这份指南回答两个问题：一个 WHR 程序应该怎样组织，以及怎样把一个需求稳定地拆成可验证的语言代码。它是实践手册，不替代冻结的[语言规范](../language/01_WHR语言规范.md)、[标准库](../language/02_标准库.md)和[错误模型](../language/03_错误模型.md)。

## 1. 先掌握四条设计约束

1. WHR 是动态类型、整数优先的脚本语言。v1.0 没有浮点数、模块、异常捕获、文件 I/O 或类继承。
2. 条件必须是 true 或 false。没有数字、字符串、数组或 null 的隐式真值。
3. WHR 不做隐式转换。字符串拼接整数必须显式写成 "score=" + to_string(score)。
4. 结构构造必须写 form Type { ... }。shape 负责声明字段，form 负责创建实例。

这些限制是为了让程序行为可预测、错误可定位、黑盒输出可复现；写程序时不要用其他语言的习惯去“猜” WHR 行为。

## 2. 推荐的程序结构

小程序可以直接从全局代码开始；稍大的程序推荐按以下顺序组织：

~~~text
# 1. shape 声明：描述需要长期保存的状态
shape ...

# 2. craft 声明：把计算和状态更新拆成可测试的小函数
craft ...

# 3. 全局初始化：创建数组、结构实例和配置值
let ...

# 4. 主流程：read/show、when、repeat while 和函数调用
...
~~~

WHR 没有模块系统，因此一个文件就是一次 CLI 执行单元。把“数据是什么”“操作是什么”“主流程怎么走”分开，有助于在验收时逐层演示，也便于为每一层写 .whr 黑盒用例。

## 3. 类型与表达式

### 3.1 基本值

~~~whr
let count <- 3;             # integer
let title <- "WHR";         # string
let ready <- true;           # boolean
let missing <- null;         # null
~~~

加号可以做整数加法或两个字符串连接；减号、乘号、除号和模运算只接受整数。比较运算只接受同为整数或同为字符串的两个值。相等运算不会进行类型转换，所以 1 == "1" 是 false。

### 3.2 求值顺序和优先级

函数实参、数组元素、结构字段值和普通表达式都从左到右求值。赋值 <- 是右结合，其余二元运算按算术、比较、布尔层次结合；需要精确规则时查看规范第 6 节。

~~~whr
let result <- 2 + 3 * 4;       # 14
let same <- (2 + 3) * 4;       # 20
let both <- result == 14 and true;
~~~

and 与 or 短路：false and missing 不读取 missing，true or missing 也不读取它。这既是语义规则，也是安全地写保护条件的常用方式。

## 4. 作用域与变量

每个花括号块创建一个作用域；函数调用创建参数和局部变量作用域。内层 let 可以遮蔽外层名称，但普通赋值会从当前环境向外寻找最近绑定：

~~~whr
let score <- 1;
{
    let score <- 2;
    score <- score + 1; # 修改内层 score
    show(score);         # 3
}
show(score);             # 1
~~~

因此要判断赋值修改了哪个状态，先查找最近的同名 let。如果名称根本不存在，运行时会报 undefined name。同一作用域内不能重复声明相同名称。

## 5. 数组和结构：什么时候用哪一个

数组适合“同类或顺序数据”，结构适合“有名字的状态字段”：

~~~whr
let scores <- [92, 88, 96];
scores[1] <- 90;
push(scores, 100);

shape Student {
    name;
    scores;
}
let student <- form Student { name: "Alice", scores: scores };
student.name <- "Bob";
~~~

数组下标从 0 开始，必须是整数且不能越界。push、pop、索引赋值和字段赋值都是原地修改。数组和结构实例赋值会复制引用而不是深拷贝：

~~~whr
let alias <- student.scores;
push(alias, 101);
show(student.scores); # 也能看到 101
~~~

结构字段初始化允许不同于声明的书写顺序，但每个字段必须恰好出现一次；运行时显示仍按 shape 的声明顺序。form 后的类型名必须解析为已经声明的 shape_type。

## 6. 函数与闭包

函数应优先做一件清楚的事，并通过参数和 give 连接主流程：

~~~whr
craft total(items) {
    let result <- 0;
    let i <- 0;
    repeat while i < len(items) {
        result <- result + items[i];
        i <- i + 1;
    }
    give result;
}
~~~

函数调用要求实参与形参数量完全一致。没有 give 或使用 give; 都返回 null。嵌套函数捕获声明时的环境：

~~~whr
craft threshold_checker(limit) {
    craft check(value) {
        give value >= limit;
    }
    give check;
}
let pass <- threshold_checker(60);
show(pass(75)); # true
~~~

这类闭包适合把配置值固定下来。不要假设 WHR 有尾调用优化或异常捕获；递归必须有明确的终止分支，错误会传播到 CLI。

数组和结构作为参数传递对象引用，所以“查询函数”和“修改函数”最好在命名和文档中区分清楚：

~~~whr
craft add_score(student, score) {
    push(student.scores, score);
}
~~~

## 7. 控制流惯用模式

### 7.1 保护分支

把非法或终止条件放在函数前面，可以减少嵌套：

~~~whr
craft absolute(value) {
    when value < 0 {
        give -value;
    }
    give value;
}
~~~

### 7.2 计数循环

WHR 只有 repeat while，通常显式维护索引：

~~~whr
let i <- 0;
repeat while i < len(scores) {
    show(i, scores[i]);
    i <- i + 1;
}
~~~

每轮先检查条件，再进入块；continue 会回到下一次条件判断，break 只离开最近一层循环。嵌套循环中如果需要结束外层循环，应通过状态变量或函数拆分表达，不能期待 break 一次跳出多层。

### 7.3 分支链

otherwise when 从上到下只执行第一个成立分支；没有成立分支且没有最后的 otherwise 时什么也不做。所有条件都必须是布尔值。

## 8. 输入、输出和标准库边界

标准输入输出保持简单，适合命令行小工具：

~~~whr
let text <- read("value: ");
when text == null {
    show("EOF");
} otherwise {
    show("received", text, len(text));
}
~~~

read 删除行末的 \n 和可选 \r，EOF 是 null。show 无参数输出空行，有参数时按 WHR 文本表示输出。需要把用户输入转成整数时调用 to_int；它只接受整数或严格的 -?[0-9]+ 字符串，不接受 +1 或前后空格。

当前标准库的边界是 show、read、len、push、pop、to_int、to_string、type_of。没有文件读写、网络、随机数、时间、正则或第三方库；需求需要这些能力时，应在报告中说明 v1.0 边界，而不是悄悄发明语法。

## 9. 从需求拆成 WHR 程序

可以按以下顺序把自然语言需求变成可验收代码：

1. 列出状态：哪些值会变化，决定使用整数、数组还是 shape。
2. 列出操作：每个操作写成一个 craft，明确参数、是否修改引用和返回值。
3. 写一个固定输入的最小主流程，先让 show 输出稳定结果。
4. 为边界写分支：空数组、EOF、越界、重复字段和错误输入都要有明确行为。
5. 把循环的索引初始化、终止条件和更新语句分开写，避免死循环。
6. 先 --check，再运行固定输入；最后把程序复制到 tests/cases/ 并固定 .stdout、.stderr 与退出码。

例如“计算成绩平均分”可以拆成：Student 或数组保存数据，sum 函数遍历数组，average 函数做整数除法，主流程用 show 展示结果；这比把所有逻辑塞入一个循环更容易讲解和测试。

## 10. 验证和交付习惯

单个程序：

~~~bash
python -m whr --check examples/guide_demo.whr
python -m whr examples/guide_demo.whr
~~~

项目级验证：

~~~bash
python -m tests.run_all
python -m unittest discover -s tests -p 'test_*.py'
python -m compileall -q whr tests benchmarks
~~~

调试时保留最小复现和实际 stderr，不要只写“程序失败”。错误类别、文件、行列和退出码是 WHR 的可观察接口；定位流程和常见修复见[调试与错误指南](03_调试与错误指南.md)。
