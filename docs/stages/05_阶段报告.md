# 阶段 5 报告：WHR 与 Python 性能对比

日期：2026-09-26

阶段状态：完成

## 1. 阶段目标

用相同算法和输入比较 WHR 与 Python 的端到端运行时间，保留完整原始数据、环境和 Git provenance，形成可以一条命令复现的性能报告。

## 2. 工作负载

### `prime_count`

- 输入：2 到 3000；
- 算法：每个候选数从 2 试除到 `divisor * divisor > candidate`；
- 校验输出：`prime_count: 430`；
- 文件：`benchmarks/prime_count.whr` 与 `benchmarks/prime_count.py`。

### `container_update`

- 输入：4000 个数组元素，6 轮索引更新；
- 算法：循环构建数组、双层循环原地更新、循环求校验和；
- 校验输出：`container: 1998000 4000 18 995`；
- 文件：`benchmarks/container_update.whr` 与 `benchmarks/container_update.py`。

Python 版本没有使用素数库、列表推导、`sum` 或向量化捷径，控制结构与 WHR 版本逐句对应。

## 3. 实验协议

1. 先分别执行 WHR 和 Python，只有 stdout 相同、stderr 为空、退出码为 0 才继续；
2. 每个工作负载进行 2 次预热；
3. 进行 7 轮正式计时，奇数轮 WHR 先运行，偶数轮 Python 先运行；
4. 使用 `perf_counter_ns` 测量独立子进程端到端墙钟时间；
5. 保存 validation、warmup、formal 的每一次运行；
6. 失败、超时和输出不一致不计入成功统计，并使命令返回非零。

端到端时间包含进程启动、文件读取，以及 WHR 特有的词法分析、语法分析和树遍历解释执行。

## 4. 正式结果

实验基线：Git `933df4b013fc6c374cc3dc07d40dc1fcb46841e3`，运行前 `git_dirty=false`。

| 工作负载 | WHR median | Python median | WHR/Python | WHR min—max | Python min—max |
|---|---:|---:|---:|---:|---:|
| prime_count | 102.773 ms | 15.040 ms | 6.83× | 101.607—103.772 ms | 14.613—16.074 ms |
| container_update | 136.348 ms | 17.408 ms | 7.83× | 134.568—138.430 ms | 16.663—17.534 ms |

两组各有 7 个 WHR 和 7 个 Python 正式样本，共 28 个正式样本，失败数为 0。精确逐轮数值以 `benchmarks/results/2026-09-26.json` 为准；上表和详细 Markdown 报告来自同一原始文件。

## 5. 结果解释

WHR 当前比等价 Python 脚本慢约 6.83—7.83 倍，主要原因是：

- WHR 每次运行都要在 Python 进程中额外执行 Lexer 和 Parser；
- 树遍历解释器对每个 AST 节点进行 Python 方法分派和动态类型检查；
- WHR 变量查找经过自定义环境链，数组内建也要经过语言调用分派；
- Python 本身使用成熟的字节码虚拟机和高度优化的内建对象。

这个结果不是失败。课程要求是比较并分析，而不是要求自研解释器超过 Python。报告真实展示开销，且两种实现都先通过了输出校验。

## 6. 主审发现与修复

第一次正式运行中，数值全部有效，但 JSON 把干净工作区错误标记为 `git_dirty=true`。原因是辅助函数把 Git 的空 stdout 转为 `None`，再用 `None != ""` 判断。

该快照被移动到忽略目录 `benchmarks/results/tmp/rejected_dirty_flag.*`，没有作为最终证据。修复加入三种回归测试：空状态为 false、非空状态为 true、Git 不可用为 null。提交修复后在干净工作区重新执行完全相同实验，最终 JSON 正确记录 `git_dirty=false`。

## 7. 交付与复现

- 原始数据：`benchmarks/results/2026-09-26.json`；
- 自动报告：`docs/performance/性能测试报告.md`；
- 方法说明：`benchmarks/README.md`；
- 驱动器：`benchmarks/run_benchmarks.py`。

复现命令：

```bash
python -m benchmarks.run_benchmarks \
  --repetitions 7 \
  --warmups 2 \
  --output benchmarks/results/reproduced.json \
  --report docs/performance/复现实验报告.md
```

不同机器或系统负载会产生不同耗时，因此复现重点是输出一致、无失败、实验协议相同和倍率处于可解释范围，而不是逐纳秒一致。
