# 阶段 1 报告：WHR v1.0 语言规范冻结

日期：2026-09-26

阶段状态：完成

## 1. 阶段目标

在解释器编码前定义完整、可实现、可测试的语言合同，使解释器、黑盒测试、人类指南和 AI 指南拥有同一个事实来源。

## 2. 交付物

- `docs/language/01_WHR语言规范.md`：词法、EBNF、类型、作用域、表达式、数组、结构、控制流、函数、I/O、CLI；
- `docs/language/02_标准库.md`：全部内建函数及边界；
- `docs/language/03_错误模型.md`：诊断格式、类别和退出码；
- `docs/language/04_规范示例与预期行为.md`：实现前纸面测试；
- `examples/language_tour.whr`：覆盖主要语言功能的完整示例；
- `.gitignore`：隔离缓存、构建产物和当前目录下与 WHR 无关的课程材料。

## 3. 关键设计决策

### 是什么

WHR v1.0 是动态类型、严格布尔、词法作用域的树遍历解释语言。它支持任意精度整数、字符串、布尔、null、可变数组、可变结构实例、函数和少量内建函数。

### 为什么这样设计

- 严格布尔和禁止隐式转换能让错误更早暴露，语义更容易讲解和测试；
- 左箭头、`shape`、`craft/give`、`when/otherwise` 等组合形成自己的语言外观；
- 只保留整数可避免浮点精度和格式化分散课程重点；
- 词法作用域和闭包体现解释器环境链的核心思想，但无需引入类或模块；
- 标准库保持最小，足够支持性能脚本和 200+ 行应用。

### 如何实现

后续 Lexer 按最长匹配生成带行列的 Token；递归下降 Parser 按 EBNF 和优先级生成 AST；Interpreter 使用环境链解析变量，用专门的控制流信号实现 `give`、`break` 和 `continue`。

### 如何证明

规范示例表逐项给出合法性、输出或错误类别。阶段 2—4 会把每一项变成真实黑盒用例，并以 CLI 的 stdout、stderr 和退出码验证。

## 4. 阶段 2 主审勘误

实现主审用 `when ok { ... }` 反例发现，原草案的 `Student { ... }` 结构构造与标识符条件后的代码块存在语法歧义。规范、示例、Parser 和测试统一改为 `form Student { ... }`。同时明确结构声明至少包含一个字段、数字只允许 ASCII `0`—`9`。这是实现早期的合同修正，已保留原因和回归场景。

## 5. 明确不包含的范围

v1.0 不包含浮点数、类、继承、模块、文件/网络 I/O、异常捕获、并发、生成器、随机数和 REPL。这些功能不是作业硬性要求，也不是综合应用的必要条件。

## 6. 纸面验证结果

- 六类硬性能力均在语法和语义中出现：基本类型、数组、结构、I/O、分支循环、函数；
- EBNF 覆盖所有关键字和运算符；
- 运算优先级、结合性和求值顺序已定义；
- 作用域、遮蔽、赋值查找和闭包行为已定义；
- 数组与结构的可变性、边界和相等规则已定义；
- 错误格式和退出码可以直接用于黑盒测试；
- 完整导览程序可按规范推导确定输出。

当前尚无解释器，因此不能声称示例已经真实执行。这是阶段 2—3 的验证任务。

## 7. 风险与下一阶段接口

主要风险是实现细节与冻结规范不一致。阶段 2 必须以 EBNF、优先级和错误模型为编码依据；发现规范缺陷时，不得只改代码，必须记录并同步更新规范、示例和后续测试。

阶段 2 的验收入口：

```bash
python -m whr --version
python -m whr --check examples/language_tour.whr
python -m whr examples/hello.whr
```

阶段 2 先实现 CLI、Token、Lexer、表达式/语句 AST、递归下降 Parser、基本环境和基本表达式执行，不提前实现完整数组/结构/函数运行时。
