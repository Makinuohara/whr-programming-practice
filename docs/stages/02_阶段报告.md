## 4. 主审发现与返工

初版代码能通过 Agent 自测，但 Sol 主审增加反例后发现：

1. `when ok { ... }` 会把 `ok {` 误判成结构初始化；
2. Python `isdigit()` 会接受规范外的 Unicode 数字；
3. 空结构声明与规范意图不一致。

返工后采用 `form Student { ... }` 消除语法歧义，只接受 ASCII `0`—`9`，并在 Parser 中拒绝零字段结构。相应规范、示例和回归测试已同步更新。这一过程体现“规范—实现—测试”三方联动，而不是只修补单个示例。

## 6. 如何在验收时讲解

### 是什么

解释器已经能够把 `.whr` 文本转换成 Token，再转换成 AST，最后通过环境链和树遍历执行基础程序。

### 为什么这样设计

递归下降 Parser 的每个函数对应一层语法规则，容易把代码与 EBNF 对照；环境链直接表示“当前作用域—外层作用域”的查找关系；树遍历执行器虽然不如字节码虚拟机快，但结构清晰，适合课程讲解和功能扩展。

### 如何实现

Lexer 保存每个 Token 的行列；Parser 按优先级从赋值逐层下降到基本表达式；Interpreter 根据 AST 节点类型执行；块创建新 Environment，赋值沿父链寻找最近绑定；`break` 和 `continue` 用内部控制流信号跳出普通遍历。

### 如何证明

自动测试既直接测试 Lexer/Parser/Interpreter，也以子进程运行真实 CLI，断言 stdout、stderr 和退出码。`--check language_tour.whr` 还证明完整语法在高级运行时尚未实现前已经可以解析。
