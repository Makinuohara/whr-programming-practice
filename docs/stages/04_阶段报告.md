# 阶段 4 报告：完整 WHR 黑盒测试集

日期：2026-09-26

阶段状态：完成

## 1. 阶段目标

不依赖解释器内部实现，以用户真实使用方式启动 `python -m whr FILE.whr`，自动验证 WHR v1.0 的全部功能、边界和错误行为，并提供一个命令运行全部测试。

## 2. 黑盒测试为什么是黑盒

测试主体是 `tests/cases/` 中的 `.whr` 源程序。`tests/run_all.py` 不导入 Lexer、Parser 或 Interpreter 来执行程序，而是为每个用例创建一个独立子进程，只观察四项外部行为：

1. 标准输入；
2. 标准输出；
3. 标准错误；
4. 进程退出码。

因此即使未来重写解释器内部结构，只要 WHR 的可观察语义不变，这套测试仍然有效。

## 3. 用例格式

每个 `case.whr` 可以配套：

- `case.stdout`：精确标准输出，缺失表示空；
- `case.stderr`：精确标准错误，缺失表示空；
- `case.json`：stdin、期望退出码、标签和超时。

错误测试不只判断“程序失败”，而是同时固定错误类别、文件、行列、说明和退出码。驱动器遇到超时、元数据错误或 0 个用例都会报告失败。

## 6. 主审附加验证

Sol 在正常全绿之外执行了故障注入：给一个内存中的 Case 添加错误期望，runner 能判定失败并生成包含 expected/actual 的 unified diff。另用不存在的筛选条件模拟 0 个用例，runner 输出 `Discovered 0 cases; refusing to report success.` 并返回退出码 1。

这证明测试驱动器不是“无论如何都返回成功”，也不会把未发现测试误报为通过。

## 7. 验收讲解要点

- `.whr` 才是测试逻辑，Python runner 只是提供输入和比对进程结果；
- 正常测试证明功能能用，错误测试证明解释器能稳定拒绝非法程序；
- 独立子进程避免一个用例的全局状态污染另一个用例；
- 精确 stderr 和退出码让错误接口也成为语言合同；
- 分类统计和覆盖矩阵使“完整”可以逐项检查，而不是靠口头声明。
