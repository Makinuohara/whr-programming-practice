# WHR 验收常见问答

## 1. 为什么叫 WHR？它与已有语言有什么区别？

WHR 用姓名首字母命名。它借鉴了常见脚本语言的动态类型和块结构，但组合了 `<-`、`form`、`craft`、`give`、`when`、`repeat while` 等自己的表面语法，因此不与某一种现有语言完全相同。

## 2. 为什么选择 Python 实现解释器？

课程重点是语言设计和解释执行机制。Python 标准库足以实现词法器、递归下降解析器和树遍历解释器，代码短、结构直观，也便于展示 AST、作用域和错误处理。解释器本身不依赖第三方库。

## 3. 为什么使用树遍历解释器，而不是编译成字节码？

树遍历模型能直接对应“语法节点如何执行”，更适合有限课时内完整实现和讲解。代价是重复遍历对象和动态分派较多，性能低于字节码虚拟机；性能报告如实反映了这一点。

## 4. 如何处理运算符优先级？

Parser 使用分层递归下降：赋值、逻辑或、逻辑与、相等、比较、加减、乘除、单目、调用/索引/字段、主表达式逐层解析。越靠下的层级绑定越紧。

## 5. 函数为什么能形成闭包？

定义函数时保存当前 Environment 作为 closure。调用时创建以 closure 为父环境的新 Environment，再绑定参数。函数返回后，内部函数仍持有它定义时的外层环境，所以捕获变量不会丢失。

## 6. 为什么条件不允许整数自动当布尔值？

严格布尔能避免 `0`、空字符串、空数组的隐式规则不一致，使语义和错误测试更明确。需要比较时应写成 `x != 0`，意图更清楚。

## 7. 黑盒测试为什么比单元测试更重要？

作业交付的是“能够执行 WHR 的解释器”。黑盒测试从 `.whr` 文件启动真实命令，验证输出、错误和退出码，最接近用户实际使用。单元测试用于补充内部边界，但不能代替进程级验收。

## 8. 64 个用例如何覆盖所有功能？

用例分成类型 8、数组 5、结构 5、I/O 6、控制流 6、函数 8、错误 22、回归与 CLI 4。功能既有正常路径，也有类型错误、越界、未知字段、参数数量不匹配等失败路径。

## 9. 性能比较是否公平？

两个实现使用相同算法和固定规模，先校验输出，再预热 2 次、正式运行 7 轮，并交替执行顺序。报告保留全部正式样本和失败状态。测量是独立子进程端到端时间，因此包含启动和 WHR 解析开销；报告明确写出这一局限。

## 10. 为什么 WHR 比 Python 慢 6 到 8 倍？

WHR 解释器由 Python 实现，每个 WHR 操作还要经过 Python 对象、AST 节点分派和环境查找，相当于在 Python 之上再解释一层；端到端计时还包含词法与解析。这个结果说明当前实现的代价，不代表所有 WHR 实现都固定慢这个倍率。

## 11. Agent 在项目里真正做了什么？

Agent 按阶段任务实现代码和文档，主智能体负责规范、验收标准、审查和返工。校园应用生成后，主审发现 Burnout 结局不可达，要求修改阈值并加入四结局子进程测试。开发日志保留了这次问题和修订，而不是只记录成功结果。

## 12. 如何证明给 AI 的 Skill 有效？

使用一个新的独立 Agent，只给它项目 Skill 和任务，不提供主开发过程上下文。它独立生成 `examples/agent_skill_validation.whr`，成功使用结构、数组、函数和循环，并通过语法检查与真实执行。结果记录在 `docs/agent_logs/06_skill_forward_test.md`。

## 13. 应用为什么使用确定性事件而不使用随机数？

确定性设计使相同输入产生相同输出，便于黑盒测试、课堂演示和问题复现。游戏性仍来自多状态权衡与不同选择路径。未来可以在标准库加入随机数后扩展可选随机模式。

## 14. 当前语言还有哪些局限？

目前没有浮点数、模块系统、异常捕获、文件 I/O、类继承和字节码优化。标准库规模也较小。这些是有意控制的 v1.0 边界，不影响作业要求；未来可优先增加模块系统和字节码虚拟机。

## 15. 如果继续优化，你会先做什么？

第一步把 AST 编译为简单字节码，减少递归对象分派；第二步缓存变量解析深度；第三步区分启动、解析和纯执行时间做剖析。优化前仍会保留现有黑盒套件作为语义回归门槛。
