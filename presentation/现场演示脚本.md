# WHR 现场演示脚本

## 演示前准备

在仓库根目录打开终端，确保使用 Python 3.11 或更高版本。提前运行一次 `python scripts/check_project.py`，但不要在正式讲解时重新生成性能结果。

## 演示 1：语言核心功能（约 45 秒）

```bash
python -m whr examples/language_tour.whr
```

指出源程序包含结构、数组、函数、循环、字段访问和分支。预期最后三类输出包括学生名、分数数组、平均分和 `level: excellent`。

接着演示只检查不执行：

```bash
python -m whr --check examples/language_tour.whr
```

预期退出码为 0 且不产生程序输出。

## 演示 2：完整黑盒测试（约 45 秒）

```bash
python -m tests.run_all
```

预期显示发现 64 个用例并全部通过。解释测试检查真实进程的 stdout、stderr 和退出码。

## 演示 3：267 行应用（约 2 分钟）

先证明行数：

```bash
python scripts/count_whr_loc.py apps/campus_survival/main.whr --minimum 200
```

预期有效行数为 267，最低 200 行检查通过。

为控制时间，使用固定输入完成一条可重复路线：

```bash
python -m whr apps/campus_survival/main.whr < apps/campus_survival/demo_input.txt
```

指出六周中五种行动全部出现，最终输出 `Ending: Campus leader ending`。如果老师希望互动，可以直接运行不带重定向的命令并手动输入姓名与六次选择。

## 演示 4：性能证据（约 45 秒）

打开：

- `benchmarks/results/2026-09-26.json`
- `docs/performance/性能测试报告.md`

说明正式数据包含两种负载、WHR/Python 两种实现、各 7 轮正式样本且 0 失败。不要现场重跑基准测试，因为当时机器负载变化会让数值波动；脚本仍保留在仓库中供复现。

## 演示 5：统一总验收（约 45 秒）

```bash
python scripts/check_project.py
```

预期所有项目显示 PASS，最终退出码为 0。结束语：这条命令把交付物、解释器、测试、应用规模和性能证据连成一个可复核闭环。

## 备用方案

- 若现场时间很短，只运行黑盒测试、应用固定输入和统一项目检查。
- 若终端字体显示异常，使用 PDF 展示架构和结果，命令本身仍可复制执行。
- 若性能被追问，展示已经保留的 JSON，不用现场临时计时替代正式结果。
