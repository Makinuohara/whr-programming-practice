# WHR 课程设计验收讲稿

## 总体讲法

每一部分都按“是什么—为什么这样设计—如何实现—如何证明”来讲。不要只念代码，也不要只报功能；重点说明设计选择和验证证据。

## 第 1 页：项目概览

WHR 是我为程序设计实践设计的解释型通用脚本语言。项目不仅包含解释器，还包含完整黑盒测试、性能对比、人类与 AI 开发指南、267 行综合应用和 Git 历史。我的目标是让它做到可运行、可测试、可复现、可讲解。

## 第 2 页：要求与证据

作业的每个评分项都能对应到仓库证据：解释器用命令运行，测试有 64 个进程级用例，性能有 JSON 原始数据和自动报告，指南经过独立 Agent 验证，应用有行数检查与四条结局测试。这样验收时不是口头声明，而是能现场复核。

## 第 3 页：语言特色

WHR 使用 `<-` 赋值，用 `form` 声明结构，用 `craft` 和 `give` 定义函数与返回值，用 `when`、`otherwise`、`repeat while` 表达控制流。这些关键字形成自己的表面语法，不与某一种现有语言完全相同。语义采用动态类型、词法作用域、严格布尔条件和短路逻辑，目的是减少歧义并便于解释。

## 第 4 页：解释器架构

源文件先经过 Lexer 变成 Token，Parser 按表达式优先级构造 AST，Interpreter 遍历 AST，并在 Environment 中保存变量和函数闭包。每层职责单一，所以我可以分别定位词法、语法和运行时错误。这是一个典型的树遍历解释器，结构清楚，适合课程项目讲解。

## 第 5 页：运行时能力

基本值包括整数、字符串、布尔值和 `none`；复合值包括数组和用户结构。数组支持索引、更新、`push`、`pop`，结构支持字段读写。函数支持参数、返回、递归和词法闭包。`when` 和 `repeat while` 只接受真正的布尔值，避免把 0 或空字符串隐式当作真假。

## 第 6 页：错误模型

错误分为 LexError、ParseError 和 RuntimeError。诊断尽量带行列位置，并规定退出码：0 表示成功，1 表示 WHR 程序错误，2 表示命令行使用错误。这个设计不只是改善体验，也让黑盒测试可以稳定检查 stderr 和退出码。

## 第 7 页：黑盒测试

测试驱动器不是调用解释器内部函数，而是启动真实进程，给它 `.whr` 文件和 stdin，再比较 stdout、stderr 与退出码。64 个用例覆盖类型、数组、结构、I/O、控制流、函数、错误和回归；此外还有 31 个 Python 单元与集成测试。重点是证明用户可观察行为，而不是内部函数碰巧通过。

## 第 8 页：性能实验

我选择素数统计和容器更新两个语义等价负载。每个实现先预热 2 次，再正式运行 7 轮，并交替 WHR 与 Python 的执行顺序。正式轮次全部成功。WHR 的端到端中位数分别约为 Python 的 6.83 倍和 7.83 倍。这个差距符合树遍历解释器还包含启动、词法和解析开销的特点；我保留全部原始结果，不只展示最快一次。

## 第 9 页：Agent 开发指南

项目中既有人类指南，也有 `.agents/skills/whr-language/` 项目 Skill。Skill 告诉 Agent 应先读哪些规范、如何实现、怎样运行 `--check` 与真实程序、交付哪些证据。为了验证它不是摆设，我让一个独立 Agent 只依靠 Skill 编写新程序，成功使用结构、数组、函数和循环并通过解释器。

## 第 10 页：综合应用

校园生存模拟器有 267 个有效 WHR 代码行。玩家连续六周在学习、休息、社团、兼职和运动中选择，系统更新多项状态、触发确定性事件并判定四种结局。它综合使用结构、数组、函数、分支、循环和 I/O。主审时曾发现 Burnout 结局不可达，返工后四条结局都用真实子进程测试覆盖，这也体现了 Agent 生成后仍需审查。

## 第 11 页：Git 与复现

项目从总体计划、规范冻结、解释器、测试、性能、指南到应用都按阶段提交。历史能够回答“什么时候加入了什么、为什么改变”。最后的 `scripts/check_project.py` 把交付物检查、CLI、黑盒测试、单元测试、应用行数和性能证据合并成一次总验收。

## 第 12 页：演示与结论

现场按五步演示：运行语言导览、运行黑盒测试、演示校园应用、展示性能原始 JSON 与报告、执行统一项目检查。WHR 的最终价值不只是“能跑”，而是形成了规范、实现、验证、实验、文档与应用之间的完整闭环。

## 一句话总结

我设计并实现了一个有独立语法的树遍历解释型语言，并用黑盒测试、可复现性能实验、Agent 前向验证和 267 行综合应用证明它可以被可靠使用。
